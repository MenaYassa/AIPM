Regression coverage lives in `tests/test_update_rollback.py` (10 tests). The P1 **independent update verifier** is also implemented at repository level: `UpdateVerifier`/`UpdateVerification` (`src/aipm/services/update/verifier.py`, `src/aipm/models/verification.py`) is a distinct component from planning and execution that compares health-before and health-after reports and returns a typed success/warning/failure verdict (warnings are explicitly not rollback conditions; critical findings or an unevaluatable post-update state fail safe and enter the same rollback path as an execution failure), with the verdict recorded additively in `UpdateAudit.verification`. Regression coverage lives in `tests/test_update_verifier.py` (11 tests). The P0 **Git transaction safety** workstream is also implemented at repository level: `GitTransactionRunner` (`src/aipm/services/update/git_transaction.py`) runs the update's Git phases (safety stash including untracked files, fetch, pull, stash apply, stash drop) as one typed transaction whose outcome (`GitTransactionResult`, `src/aipm/models/git_transaction.py`, completed with `stash_preserved`) is recorded additively in `UpdateAudit.git_transaction`; the stash is dropped only after a successful apply, is preserved for manual recovery on any apply failure with the exact conflicting files reported, and no checkout/reset/clean ever runs, so operator changes are never silently discarded. Failures raise `GitTransactionError` (an `UpdateError` subclass) carrying the typed result and enter the same snapshot-restore rollback path as an execution failure. Regression coverage lives in `tests/test_update_git_transaction.py` (13 tests). Mission Control completion does not imply completion of that broader product roadmap.
